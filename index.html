How to Use Rate Compare

Compares what customers were actually charged (AI pricing) against what a static rate table would have charged for the same visits.

1. Where to get the data

  1. Open the Visit Details dashboard.
  2. Filter to the site and date range you want to analyze.
  3. Download the data as a CSV and drop that file into this tool, unedited. Pull a separate export for each file you need (see below).

2. Steps

  1. Setup tab: drop the visit CSV (the period you want to analyze, AI-priced). Comparison runs automatically.
  2. Optionally drop a historical visit CSV. The tool infers the static rate table (rate cards, duration bands, prices) from it. Or build/adjust rate cards by hand and use + Add Rate Card.
  3. Check the rate coverage grid: green = one rate card covers that hour, red = two or more conflict, blank = no rate (a gap, often intentional). Visits in a gap are excluded.
  4. Review Summary (totals and variance) and Full Data (per rate card, band and day of week).

3. Compare logic

  • For each visit, the tool finds the rate card matching the entry day and time, then the duration band the stay length falls in. That band's price is the static price.
  • The visit's actual price is what was really charged. Variance = Actual − Static, shown as $ and as a percent of static.
  • Totals are split into the GPV Pool (what the customer paid) and the Validation Pool (amounts covered by validations). Use Include Full Validations on Summary to add or remove the Validation Pool.
  • Only included in the comparison: pay-as-you-go Transient (No Coverage) and Validation (Fully Covered) visits.
  • Excluded (listed under Excluded on Full Data): special event rates, stays longer than the reconciliation cutoff (default 24 hours), subscriptions, reservations, partial validations, visits with missing or bad timestamps, visits that match no rate card, and (when scan-to-pay applies) off-pattern durations.
  • Scan to pay: Auto-detect checks whether durations fall on the scan-to-pay time grid. If so, off-grid visits are excluded. Override with On or Off if the detection is wrong.

4. When to use Early Bird

  • Turn on Add Early Bird (Setup) only if the site actually has an early bird flat rate.
  • Set the entry window (start and end time), the days it applies, the exit condition (Exit Before or Exit After a time) and the flat price.
  • A visit that qualifies is priced at the flat Early Bird price and overrides the normal rate card bands. It never gets both.
  • If you also drop a historical CSV, Re-run Inference from Historical Data can fill in the Early Bird price from past visits.
  • On Summary, Include Early Bird adds or removes Early Bird visits and revenue from the totals, so you can see results with and without it.
  • Leave it off for sites with no early bird. Those visits then just fall into the regular rate cards.

5. When to use Volume Compare

  • Drop a Volume Compare CSV (usually the same site, a year earlier, any length) to compare against the AI Pricing visit file. Export it from the same dashboard.
  • Optional. The Volume Compare tab stays disabled until that file is loaded, and it also needs the current visit CSV.
  • Matching days: both sides use the same number of days, starting on the same weekday (4 Mondays vs 4 Mondays; 3 vs 3 if the AI file is shorter). The comparison start is the same-weekday date closest to the same calendar date one year earlier. If the comparison file is longer, only the best-matching slice is used. The tab shows the exact dates compared.
  • What it shows: for each rate card, by band and day of week, the Volume (visits) and Average Ticket Price, plus the change as a number and a percent. Headline bubbles roll this up across all rate cards.
  • Both sides are bucketed into the same bands from the current rate table, with the same exclusions and Early Bird setting.
Tip: Volume Compare trims to equal, weekday-aligned windows automatically, but holidays and events inside the windows can still skew volume.
